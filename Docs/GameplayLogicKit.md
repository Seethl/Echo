# Механіки без змін локації

Гілка: `feature/puzzle-and-enemy-logic`, основа — `feature/sound-progression`.
Цей пакет не редагує сцени, префаби, матеріали, меню, UI, радіо та інші
локаційні об'єкти. Нові компоненти не додаються до маєтку автоматично.

## Розподіл роботи

- Розробка механік: `Scripts/Puzzles/`, `Core/ObjectiveSequence.cs`,
  `Enemy/EnemyInvestigator.cs`, перевірки у `Core/`.
- Розробка локації: сцени, префаби, освітлення, радіо, меблі, колайдери,
  візуальна/звукова атмосфера та підключення готових компонентів до об'єктів.
- Перед спільною інтеграцією узгодити конкретні objective ID та об'єкт
  `GameProgression`, який використовують істота й звуковий інструмент.

## Головоломка на слух

`SoundSequencePuzzle` — компонент із власним AudioSource. Його можна поставити
на контролер головоломки; він не перехоплює радіо, глобальне аудіо чи клавіатуру.

Приклад параметрів: `tones = [низький, середній, високий]`, `sequence = [0, 2, 1, 0]`.
Номери починаються з нуля. Кожен номер мусить мати призначений AudioClip.
При першому зверненні конфігурація копіюється; зміни масиву посеред проходження
не підміняють відповідь. Вступна головоломка за замовчуванням не створює шуму для AI.

Публічні дії для подій важелів, кнопок або майбутнього радіо:

| Метод | Результат |
| --- | --- |
| `PlayClue()` | Відтворити підказку; повтор дозволений без штрафу |
| `SubmitTone(int)` | Подати вибраний звук |
| `ResetAttempt()` | Почати відповідь заново, не скидаючи весь рівень |
| `TryPlayClue()` / `TrySubmitTone(int)` | Те саме з поверненням результату для коду |

Потрібно спершу прослухати підказку до кінця (`requireListeningFirst`). Під час
програвання відповідь заблокована. Помилка скидає тільки спробу; ліміту часу,
втрати ключа чи покарання монстром за замовчуванням немає. Пауза/записка
блокують дії. Вимкнення компонента скасовує програвання, не зараховуючи його
як прослухане. Розв'язану головоломку не можна розв'язати повторно заради нагороди.

Події для підключення без змін скриптів:

- `onTonePlayed(int)` — єдиний номер для звуку й візуальної підказки/доступності.
- `onProgressChanged(int)` — скільки звуків введено правильно.
- `onMistake`, `onClueStarted`, `onClueFinished` — зворотний зв'язок.
- `onSolved` — відкрити механізм або завершити ціль.

Візуальний відповідник звуків бажаний: рішення має спиратися на слухання,
але не вимагати бездоганного слуху чи знання нот.

## Ланцюжок цілей

`ObjectiveSequence` — один компонент на епізод. `steps` — впорядкований список
унікальних ID, назв, етапу небезпеки після виконання та події `onCompleted`.
Порожня або некоректна конфігурація не зараховується як перемога.

Приклад (потрібно узгодити з конкретною локацією):

| ID | Виконання | Етап після виконання |
| --- | --- | --- |
| `clock.pattern` | Головоломка на слух | Awakening |
| `service.mechanism` | Відкрити наступний механізм | Danger |
| `alarm.obtain` | Отримати звуковий інструмент | SoundMastery |
| `exit.open` | Підготувати вихід | SoundMastery |

На `puzzle.onSolved` призначити `ObjectiveSequence.CompleteObjective(string)`
зі стабільним ID. Непоточна, невідома або повторна ціль ігнорується.
Завершення не може рекурсивно завершити всі наступні цілі своїми ж callback.
`onObjectiveChanged(string)` та `CurrentTitle` призначені для UI друга;
`onAllCompleted` — для узгодженого завершення епізоду. UI не створюється.
Стан живе в сцені, перезапуск починає проходження заново: це не save-система.

## Поведінка істоти

`EnemyInvestigator` зберігає старі значення станів і додає `Returning`:

`Idle → Investigating → Searching → Returning → Idle`.

Істота йде до останньої почутої позиції, оглядається протягом `searchDuration`
та повертається до своєї початкової точки. Скрипт не має посилання на позицію
гравця й не може стежити за ним після завершення шуму. Новий прийнятий звук
перериває повернення. Пріоритет приманки залишається в `NoiseListener`.

- `returnToStart = false` залишає істоту на місці після перевірки.
- `SetHome(Vector3)` змінює точку повернення для майбутнього патрулювання.
- `searchTurnAngle` керує оглядом, `onStateChanged` дозволяє підключити анімацію/звук.
- Приймаються лише повні маршрути для типу й areaMask поточного NavMeshAgent.
- Тайм-аут і перевірка фактичного руху не дозволяють безкінечно впиратися в перешкоду.
- Якщо неможливо повернутися, істота зупиняється; телепортації та проходження
  крізь двері немає. Рухомі двері потребують окремого рішення на рівні навігації
  локації — цей пакет не перебудовує її колайдери чи NavMesh.

## Тривала гучна дія

`TimedNoiseMechanism` — логіка механізму, який повинен працювати кілька секунд,
поки гравець використовує відволікання. Це не нова реалізація дверей чи радіо:
він лише створює звукові імпульси та повідомляє про завершення роботи.

- `Begin()` / `TryBegin()` запускають дію з нуля. Потрібен призначений `loopClip`
  та власний AudioSource. За замовчуванням тривалість 4 с, шум 12 м, імпульс щосекунди.
- `Cancel()` зупиняє звук і скидає лише незавершену роботу. Повторити можна.
- Пауза/записка зупиняють прогрес, звук і імпульси. Вимкнення компонента скасовує дію.
- Лише після повної тривалості спрацьовує `onCompleted`. Результат одноразовий.
- `onProgressChanged(float)` дає значення 0–1 для індикатора друга;
  `onStarted` / `onCancelled` — для анімації та зворотного зв'язку.

На `onCompleted` можна підключити `ObjectiveSequence.CompleteObjective(string)`
або вже готовий механізм локації. Початок дії сам по собі не відчиняє вихід.
Компонент не блокує керування й не вирішує, чи треба тримати важіль поруч:
об'єкт локації викликає `Cancel()` при відпусканні/відході, якщо це потрібно дизайну.

## Перевірки

Підтверджено безпосередньо в Unity 6000.6.7f1: попередній набір — 21,
новий — 41 успішна перевірка, разом 62. Console:
`Sound progression checks: 21 passed.` та `Gameplay mechanics checks: 41 passed.`
Компіляція всіх скриптів для Editor і runtime також пройшла без попереджень.

Існуюча `SoundProgressionTest` запускає попередні звукові перевірки, потім
`GameplayMechanicsChecks`. Нові перевірки створюють тимчасові об'єкти й маленьку
навігаційну ділянку далеко від рівня лише під час Play та прибирають їх після себе.
Файли сцени не зберігаються й не змінюються.

Перевіряються порядок звуків, повтори, помилки й скасування підказки, пауза,
одноразове виконання цілей та нагород, інтеграція з прогресією, досяжність
маршруту, огляд, повернення, переривання новим звуком і вихід зі застрягання.
Додатково — гучна дія, пауза, скасування, повтор, вимкнення callback і одноразовий результат.
Окремо потрібне проходження на реальній локації після підключення компонентів.
