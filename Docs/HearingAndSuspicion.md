# Слух, перешкоди та підозра

Гілка `feature/hearing-and-suspicion` продовжує `feature/puzzle-and-enemy-logic`.
Сцени, префаби, радіо, двері, матеріали та UI локації не редагуються.

## Порядок обробки шуму

1. Перевіряється етап прогресії й пауза.
2. Початковий радіус множиться на чутливість слухача.
3. Чутне фонове джерело може зменшити цей радіус.
4. Перешкоди між джерелом і вухами додатково приглушують звук.
5. Якщо звук дістався слухача, обчислюється його виразність з урахуванням відстані.
6. Застосовується короткий пріоритет приманки, потім оновлюється підозра.

Це ігрова модель слуху AI. Вона не змінює гучність у навушниках і не додає
ефектів до радіо. Master Volume гравця не визначає, чи почує його істота.

## Перешкоди

`NoiseListener.useOcclusion` за замовчуванням увімкнено. `earOffset` — локальна
позиція вух відносно об'єкта слухача (за замовчуванням 0,9 м вгору).
Радіуси залишаються у світових метрах. Слухача бажано розміщувати на корені істоти,
щоб її власні дочірні колайдери правильно ігнорувалися.

- `obstacleLayers` визначає, які тверді колайдери приглушують звук.
- Без окремого компонента кожна перешкода залишає 45% радіуса чутності.
- `AcousticObstacle.transmission` на стіні або батьківському об'єкті дверей
  задає власне значення: 0 — не пропускає, 1 — пропускає повністю.
- Колайдери одного AcousticObstacle враховуються один раз. Для об'єктів без
  профілю колайдери одного Rigidbody також рахуються як одна перешкода.
- Дві різні перешкоди з 0,5 залишають 0,25 радіуса. Шум 20 м через них має радіус 5 м.
- Trigger-об'єми, тіло джерела й тіло слухача ігноруються.
- Коли двері фізично відсуваються від променя, звук проходить вільно.

Модель перевіряє прямий відрізок: огинання стін через коридори, кімнатні портали
й товщина матеріалу не симулюються. Меблі на obstacleLayers теж приглушують звук;
на реальній локації потрібно узгодити шари або профілі, а не робити гравцю
непередбачувану акустичну перешкоду з кожного декоративного предмета.
Рухомі колайдери беруться з поточного фізичного стану Unity; код не переміщує їх.

Фоновий годинник створює прикриття лише якщо його власний звук може дістатися
слухача. Годинник за повністю звукоізолюючими дверима не дає глобального захисту.

## Підозра

`EnemySuspicion` додається автоматично як залежність нового `EnemyInvestigator`.
Для вже збережених раніше компонентів перевірити його наявність під час інтеграції;
сцени цей пакет не переписує. Істоти без активного компонента підозри зберігають
попередню пряму реакцію на почутий звук.

Стани підозри відрізняються від станів руху:

| Підозра | Реакція |
| --- | --- |
| Calm | Немає активної пам'яті про звук |
| Wary | Поворот до останньої почутої позиції, без початку руху |
| Alarmed | Запит перевірити почуте місце через існуючий навігаційний компонент |

Тихі звуки накопичують `Amount` від 0 до 1. Типові значення:
`gainPerSound = 0.4`, `investigationThreshold = 0.6`.
Виразність дорівнює `1 - distance / effectiveRadius` (мінімум 0,05 для почутого звуку).
Тому далекі кроки додають менше підозри, ніж близькі чи гучні.

Звук із виразністю від 0,8, а також чутна приманка, одразу привертають увагу.
Нечутна за стіною приманка нічого не робить. Звичайні повторні запити мають
коротку паузу 0,35 с; виразна близька дія може перебити її негайно.
Це не вмикає захоплення гравця у безпечних етапах прогресії.

Після 4 с тиші підозра спадає на 0,12 за секунду. На нулі запам'ятована позиція
скидається. Пауза зупиняє цей час. Істота не зберігає посилання на гравця й не
отримує його нових координат без наступного почутого звуку.
Завершення вже початої перевірки та повернення залишаються відповідальністю
EnemyInvestigator; спад підозри не телепортує й не оглушує істоту.

## Сигнали для інтеграції

- `onStateChanged(State)` — одноразовий сигнал переходу для пози/голосу істоти.
- `onSuspicionChanged(float)` — числове значення для відлагодження або погодженого UI.
- `onNoticedNoise(Vector3)` — отримана фіксована позиція звуку.
- `onInvestigationRequested(Vector3)` — сигнал початку перевірки; стандартний
  EnemyInvestigator викликається самим компонентом, дублювати виклик не потрібно.
- `ClearMemory()` скидає підозру й короткий пріоритет звуку. Поточний маршрут
  при цьому сам по собі не скасовується.

Не підключати `NoiseListener.onNoiseHeard` напряму до `Investigate`, якщо потрібна
підозра: такий зовнішній виклик навмисно обійде накопичення. Наявне внутрішнє
підключення оновлено й слабкий звук більше не запускає переслідування.

## Перевірки

Безпосередньо в Unity 6000.6.7f1 підтверджено: 21 попередня звукова перевірка,
43 перевірки механік/навігації та 33 нові перевірки акустики/підозри — разом 97.
Console показала 0 попереджень і 0 помилок. Компіляція Editor і runtime
також пройшла без попереджень.

`HearingAndSuspicionChecks` запускається після попередніх перевірок в існуючій
лабораторній сцені. Тимчасові стіни, рухомі перешкоди та слухачі створюються
далеко від локації лише на час Play й прибираються після перевірок.
Файли сцен і префабів не змінюються.

Перевіряються відстань, одна/дві стіни, матеріали, відкриті двері, Trigger,
шари, власні колайдери, складені двері, недоступне звукове прикриття,
накопичення підозри, сильний звук, приманка, тиша, пауза, безпечний вступ
та інтеграція накопичення підозри з реальним NavMeshAgent.
